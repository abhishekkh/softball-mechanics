## Accomplishments
- Motion Type radio selector (Hitting / Pitching, default Hitting) appears between athlete dropdown and filming tips in the upload page
- `VideoUploader` accepts `motionType` prop (optional, defaults to `'hitting'`) and includes it in the presign fetch body, with `motionType` in the `useCallback` dependency array to prevent stale closures
- Presign route validates `motionType` with `z.enum(['hitting', 'pitching']).default('hitting')` and writes `motion_type` to the videos DB row

## Files Created/Modified

- `src/components/upload/VideoUploader.tsx` - Added motionType to props interface, included in presign body, added to useCallback deps
- `src/app/api/upload/presign/route.ts` - Added motionType to PresignSchema (Zod), destructuring, and DB insert as motion_type

## Decisions Made
- `motionType` is optional in `VideoUploaderProps` with a default of `'hitting'` — preserves backward compatibility if the component is ever used without the selector in the future
- `motionType` added to the `useCallback` dependency array for `uploadFile` — prevents stale closures from sending the wrong motion type if the user changes the radio after the component mounts
- `z.enum(['hitting', 'pitching']).default('hitting')` on the server-side Zod schema — provides a server-side fallback for robustness
