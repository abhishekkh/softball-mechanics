# Phase 02.5: Review UX and Usability Across Devices, Security, Performance and Code — Context

**Gathered:** 2026-03-02
**Status:** Ready for planning

<domain>
## Phase Boundary

Audit the existing app across four dimensions — UX/devices, security, performance, and code quality — and resolve the most important issues before Phase 3. This phase makes the app production-ready, resilient, and performant. It does NOT add new features.

</domain>

<decisions>
## Implementation Decisions

### Work Mode
- Fix as we go — this is not an audit-only phase
- Rule: if a fix takes < 1 hour, do it. If it requires significant rework, log it as a todo for a later phase
- Output is a better codebase, not a findings report

### Device & Browser Coverage
- Chrome on mobile AND desktop — both are first-class
- All pages must be tested on mobile Chrome: Upload, Dashboard, Roster, Login/auth, Review
- Minimum mobile viewport: 375px (iPhone SE baseline)

### Mobile Review Page Layout
- Video player stacks on top, mechanics sidebar stacks below (no tabs or toggles)
- Simple vertical scroll — video plays, user scrolls down to see angles and flags

### Security Scope
- All security areas equally: cross-coach data isolation, unauthenticated access, API key exposure, service role key misuse, and input validation
- Audit: RLS policies (coach A cannot see coach B's athletes/videos/analyses), API route ownership checks, presigned URL expiry, middleware auth coverage, env var hygiene
- Add rate limiting on upload/presign and analysis routes — use Vercel or middleware primitives; do not build a custom solution

### Code Quality Floor (Principal Engineer Standard)
- **Error handling & resilience**: Every API route returns a consistent error shape. Client components have error boundaries. Non-fatal errors are logged with context, not swallowed silently.
- **Console.log cleanup**: Remove debug `console.log` calls. `console.error` with structured context (e.g., `[module] message: detail`) is acceptable in server code. No raw stack traces or internal error details exposed to clients.
- **TypeScript `any`**: Fix only if < 1 hour. The `profiles as any` pattern in page components (dashboard, upload, roster) is a known issue — fix if a typed Supabase join is straightforward; log for later if it requires schema changes.
- **Test coverage**: Expand Vitest coverage for mechanics detection — flags (hitting + pitching) and angle calculations. Hitting flag tests are sparse; pitching tests exist but need edge case coverage.

### Performance
- Both page load AND analysis worker smoothness are required
- Page load: Core Web Vitals (LCP, CLS, FID) for dashboard, upload, and review — especially on mobile Chrome
- Analysis worker: MediaPipe pose analysis must not block main thread or cause janky video playback during analysis
- Specific concern: dashboard may load multiple video thumbnails — check for N+1 image requests or layout shift

### Claude's Discretion
- Exact rate limiting implementation (Vercel Edge Config, middleware counter, or Upstash if available)
- Error boundary component design and placement
- Structured logging format (as long as no internal details reach the client)
- Specific Vitest test file organization

</decisions>

<specifics>
## Specific Ideas

- "The app needs to be production ready, resilient and performant" — this is the north star. Every plan should ask: would a principal engineer be comfortable shipping this?
- Mobile upload is athlete-facing (they use phones). Mobile review is coach-facing (they may check on phone but primarily use desktop). Both must work.
- Rate limiting is a quick win — if Vercel or Next.js middleware can handle it without a custom Redis/Upstash setup, do it in this phase.

</specifics>

## Existing Code Insights

### Reusable Assets
- `src/middleware.ts` — already handles auth redirect and role header injection; rate limiting logic can be added here
- `src/lib/supabase/` — Supabase client helpers; RLS audit should trace all queries back to these clients

- Auth: `supabase.auth.getUser()` (not `getSession`) — correct pattern already in place across all API routes

### Integration Points
- Rate limiting: add to `src/middleware.ts` matcher paths covering `/api/upload/presign` and `/api/analysis`

- Mobile layout: `src/components/review/ReviewPageClient.tsx` and `src/components/review/MechanicsSidebar.tsx` — flex direction change on small viewports
- RLS audit: Supabase dashboard + `supabase/migrations/` — trace each table's policies against coach_id ownership checks
