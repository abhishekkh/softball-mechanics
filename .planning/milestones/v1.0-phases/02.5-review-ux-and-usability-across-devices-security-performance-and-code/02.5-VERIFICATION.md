#### 1. Supabase Migration 008 Applied to Hosted Instance

**Test:** Open Supabase Dashboard > Authentication > Policies. Verify the `video_analyses` and `video_analysis_frames` tables show "Coaches can insert/update own video analyses" and "Coaches can insert/update own frame data" policies — NOT "Service role can insert/update analyses" with USING(true).

**Expected:** Scoped ownership policies present on both tables. Old USING(true) policies gone.

**Why human:** Docker is not running locally. `npx supabase db diff --local` cannot verify remote application state. The migration file is correct, but application to the hosted Supabase project must be confirmed manually via the Dashboard or by running `npx supabase db push`.

#### 2. Rate Limit 429 Response Behavior

**Test:** From the browser or curl, send >10 presign requests within 60 seconds to `/api/upload/presign` while authenticated. Verify the 11th request returns HTTP 429 with body `{ "error": "Too many requests" }`.

**Expected:** HTTP 429 returned; client receives `{ error: 'Too many requests' }`.

**Why human:** In-memory rate limiting resets on Edge worker cold start. The map logic is correct but behavior under Next.js dev server vs. production Edge runtime may differ. Cannot verify the 429 path triggers correctly without making live HTTP requests.

#### 3. Mobile Review Page Layout at 375px

**Test:**
1. Run `npm run dev`
2. Open Chrome DevTools > Toggle Device Toolbar > iPhone SE (375x667)
3. Navigate to any review page (`/review/[any-video-id]`)
4. Verify: video player fills width at top, scrolling reveals mechanics sidebar with angles and flags, no content clipped, all buttons reachable

**Expected:** Video on top, full-height sidebar below with natural page scroll. No horizontal overflow or cut-off content.

**Why human:** `lg:min-h-0` is a CSS flex min-height constraint. Its effect on scroll activation within a bounded flex parent requires visual inspection at the target viewport. Tailwind class presence can be verified programmatically (done) but visual correctness cannot.

#### 4. Desktop Review Page Side-by-Side Layout

**Test:**
1. Same dev server, return to desktop view (disable device emulation)
2. Navigate to the same review page
3. Verify: video and sidebar appear side-by-side (video left, sidebar ~288px right); sidebar scrolls independently when content overflows

**Expected:** Two-column layout; sidebar independently scrollable on desktop; video fills remaining horizontal space.

**Why human:** Same reason as #3 — flex overflow scroll behavior requires visual confirmation.
