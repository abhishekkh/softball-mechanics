<task type="auto">
  <name>Task 1: Fix middleware PUBLIC_PATHS — remove '/' bypass</name>
  <files>src/middleware.ts</files>
  <action>
Remove `'/'` from the `PUBLIC_PATHS` array on line 4. The array should become:

```typescript
const PUBLIC_PATHS = ['/login', '/signup', '/auth/callback', '/invite', '/api/inngest']
```

Do NOT touch any other line in middleware.ts.

Why this fixes the bug: `PUBLIC_PATHS.some(p => pathname.startsWith(p))` — since every URL path starts with `'/'`, having `'/'` in the array made `isPublicPath` always true, so `!user && !isPublicPath` was always false, and no unauthenticated request was ever redirected to `/login`.

Why removing `'/'` is safe: The landing page at `src/app/page.tsx` is a static marketing page component — it does NOT call `redirect('/login')` for null users. It renders publicly for all visitors. The middleware matcher config includes `'/'` as a matcher entry so middleware runs on the root route, but that is separate from the PUBLIC_PATHS whitelist: `matcher` controls where middleware runs; `PUBLIC_PATHS` controls whether an unauthenticated visitor is redirected. With `'/'` removed from PUBLIC_PATHS, unauthenticated visitors to `/` will have auth checked, find no user, find `/` is not public, and... wait — that would redirect `/` to login, which breaks the landing page.

CORRECTION: The landing page `/` must remain accessible to unauthenticated users. The bug is that `startsWith('/')` matches ALL paths, not just `/`. The correct fix is to use exact matching for `'/'` while keeping startsWith for prefix-based paths.

Use this updated logic in middleware.ts:

```typescript
const PUBLIC_PATHS = ['/', '/login', '/signup', '/auth/callback', '/invite', '/api/inngest']

// Replace the isPublicPath check (lines 63-65) with exact-match for '/' and startsWith for others:
const isPublicPath = PUBLIC_PATHS.some(p =>
  p === '/' ? request.nextUrl.pathname === '/' : request.nextUrl.pathname.startsWith(p)
)
```

This way:
- `/` matches only exactly `/` (landing page stays public)
- `/login` matches `/login`, `/login?error=...` etc.
- `/invite` matches `/invite`, `/invite/accept`, `/invite/[token]` etc.
- `/dashboard`, `/upload`, `/review/...` are NOT matched → unauthenticated users get redirected to `/login`

The full updated PUBLIC_PATHS declaration and isPublicPath check are the only changes needed. Everything else in middleware.ts remains identical.
