From src/components/review/MechanicsSidebar.tsx (the aside element — line ~139):
```tsx
{/* Current — potentially clips on intermediate desktop widths */}
<aside className="w-full lg:w-72 bg-neutral-900 border-t border-neutral-700 lg:border-t-0 lg:border-l flex flex-col lg:overflow-hidden">
  {/* inner scrollable content div */}
  <div className="overflow-y-auto flex-1 p-4 space-y-4">
    ...
  </div>
</aside>
```

Research finding (from RESEARCH.md):
- The `lg:overflow-hidden` on the aside restricts internal scroll to desktop only. On mobile the sidebar is `w-full` (no fixed height), so content flows naturally — correct behavior per "simple vertical scroll" decision.
- Fix: add `lg:min-h-0` to the aside element. This ensures the `flex-1` + `overflow-y-auto` inner div can activate within the flex parent on desktop. On mobile, `min-h-0` has no effect because the layout is block-level (flex-col stack).

Target class change:
```tsx
{/* Current */}
<aside className="w-full lg:w-72 bg-neutral-900 border-t border-neutral-700 lg:border-t-0 lg:border-l flex flex-col lg:overflow-hidden">

{/* Fixed */}
<aside className="w-full lg:w-72 lg:min-h-0 bg-neutral-900 border-t border-neutral-700 lg:border-t-0 lg:border-l flex flex-col lg:overflow-hidden">
```

The `lg:min-h-0` prevents the `aside` from stretching beyond the flex parent's height on desktop, enabling the inner `overflow-y-auto` div to scroll rather than expand infinitely.
