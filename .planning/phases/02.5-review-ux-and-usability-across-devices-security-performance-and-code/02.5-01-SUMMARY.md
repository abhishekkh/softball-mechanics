## Decisions Made

- `request.ip` does not exist on `NextRequest` in Next.js 16 — use `x-forwarded-for` + `x-real-ip` headers for IP detection. Plan's code snippet used `request.ip` which caused a TypeScript error; fixed to use headers only.
- `coachId` removed from PresignSchema silently via Zod's default strip behavior — no VideoUploader.tsx client changes needed.
- Migration uses `DROP POLICY IF EXISTS` for idempotency.
- Rate limit map resets on cold start — acceptable trade-off for v1 without Redis.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Fixed TypeScript error: request.ip not available on NextRequest in Next.js 16**
- **Found during:** Task 2 (middleware rate limiting)
- **Issue:** Plan's rate limiter code used `request.ip ?? request.headers.get('x-forwarded-for')` but `request.ip` does not exist as a property on `NextRequest` in Next.js 16, causing TypeScript error TS2339
- **Fix:** Changed to `request.headers.get('x-forwarded-for') ?? request.headers.get('x-real-ip') ?? 'unknown'`
- **Files modified:** src/middleware.ts
- **Verification:** `npx tsc --noEmit` passes with no errors
- **Committed in:** 60f30dc (Task 2 commit)
