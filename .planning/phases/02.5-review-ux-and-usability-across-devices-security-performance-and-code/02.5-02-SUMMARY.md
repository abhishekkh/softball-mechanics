## Decisions Made
- Used `as unknown as ProfileRow | null` double-cast rather than direct `as ProfileRow | null` — Supabase query builder infers foreign key joins as arrays (`{ full_name: any }[]`), not objects. Direct cast fails TS2352; routing through `unknown` tells TypeScript we know the shape at runtime
- Upload page filter updated to `p !== null && p.full_name !== null` then re-cast to `{ id: string; full_name: string }[]` — UploadPageClient's `athletes` prop requires non-nullable `full_name`; filtering out null-name rows is safer than asserting

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] TypeScript errors from Supabase join array inference with typed casts**
- **Found during:** Task 2 (Remove profiles as any)
- **Issue:** Direct cast `profiles as ProfileRow | null` fails TS2352 — Supabase types the join result as `{ full_name: any }[]` (array), not a single object. TypeScript refuses to cast an array to an object type without an `unknown` bridge.
- **Fix:** Changed all three casts to `profiles as unknown as ProfileRow | null`. Also updated upload page filter to exclude null `full_name` entries and added explicit re-cast to `{ id: string; full_name: string }[]` to match `UploadPageClient` prop contract.
